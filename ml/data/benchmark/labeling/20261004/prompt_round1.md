# Задание: синонимы технологий и независимая оценка карточек

Ты — независимый эксперт-аналитик технологических трендов. Выполни обе части полностью и строго по правилам ниже. Это слепая проверка: оценивай только по приложенным данным.

## Приложенные файлы

- `experts.csv` — технологические сигналы. Столбцы: `row_id`, `topic`, `title`, `description`.
- `cards.csv` — карточки «слабых сигналов». Столбцы: `card_id`, `topic`, `title`, `description`, `advantage`, `case_example`, `sources`. В `sources` — до 6 источников, по каждому указаны:
  - тип;
  - уровень доверия;
  - дата;
  - название;
  - ссылка;
  - краткое содержание.

## Общие правила (обязательны)

1. Работай только с этими двумя файлами и этим текстом. Не ищи в интернете и не открывай ссылки. Общие знания о том, насколько технология распространена, использовать можно. Но не проверяй и не дополняй факты о конкретных компаниях, статьях и сделках: опирайся на то, что написано в файлах.
2. Не задавай вопросов и не предлагай вариантов — выполни задание целиком.
3. Обработай каждую строку обоих файлов ровно один раз, в исходном порядке. Ничего не пропускай, не объединяй и не добавляй.
4. Значения `row_id` и `card_id` копируй без изменений.
5. Результат — ровно два файла: `synonyms.jsonl` и `labels.csv`.
   - Если в этом чате можно создавать файлы — создай оба для скачивания.
   - Если нельзя — выведи содержимое каждого файла целиком в отдельном блоке кода. Перед каждым блоком напиши имя файла.
6. Не сокращай вывод: никаких «…», «и так далее», «аналогично». Если ответ не помещается в одно сообщение, остановись на конце строки и напиши `ПРОДОЛЖЕНИЕ СЛЕДУЕТ`. После сообщения «продолжай» выведи следующую строку и всё, что после неё, без повторов.
7. Вне файлов пиши только итоговую сверку из раздела «Проверка перед отправкой».

## Часть 1. Синонимы технологий → `synonyms.jsonl`

Для каждой строки `experts.csv` дай от 1 до 4 альтернативных названий **той же технологии** — так, как они могли бы встретиться в заголовке научной статьи, патента, репозитория или новости.

Правила:

- Называй технологию, метод или класс решений из `title` и `description`. Не называй компанию, бренд продукта, страну, инвестора или сумму сделки.
- Название должно быть конкретным, а не общей областью.
  - Нельзя, если сигнал не про конкретную разновидность: «искусственный интеллект», «машинное обучение», «edge computing», «финтех», «робототехника», «кибербезопасность», «блокчейн», «дата-центр», «большие языковые модели».
  - Можно, например: «agent-to-agent payments», «tokenized deposits», «платежи между ИИ-агентами».
- Каждое название — от 2 до 6 слов. Аббревиатуры (LLM, RAG, IoT, NPU) отдельно не используй — только в составе фразы, например «RAG pipeline security».
- Хотя бы одно название — на английском, русские добавляй по желанию. Пиши в той форме, в какой фраза обычно стоит в заголовках (например, во множественном числе).
- Не повторяй `title` дословно.
- Если надёжного альтернативного названия нет — пустой список `[]`. Лучше пусто, чем общее слово.

Формат — одна строка JSON на сигнал, в порядке `experts.csv`:

```
{"row_id": "<row_id как в файле>", "synonyms": ["<название 1>", "<название 2>"]}
```

## Часть 2. Оценка карточек → `labels.csv`

Для каждой строки `cards.csv` поставь ровно один код.

Карточка — слабый сигнал (`R`), только если выполнены **все четыре** условия:

1. **По теме** — относится к теме из столбца `topic`, а не к соседней области.
2. **Конкретно** — конкретная технология, метод, продукт или практика, а не общая категория.
3. **Ранняя стадия** — исследование, прототип, пилот, первые внедрения, нишевый открытый код. Не массовое применение.
4. **Проверяемо** — среди `sources` есть датированный источник, из которого видно, что именно наблюдается.

Коды отказа:

| Код | Когда ставить |
|---|---|
| `N-NOI` | склейка разнородных тем, служебный или бессмысленный текст, пустое название |
| `N-OFF` | не по теме `topic` |
| `N-FUND` | рядовая новость о финансировании или сделке без технологического содержания |
| `N-OVR` | обзор, список, подборка, а не конкретная разработка |
| `N-GEN` | общее понятие, не конкретная технология |
| `N-MAT` | массовая или устоявшаяся технология |
| `N-HYP` | заявления без проверяемого содержания |
| `U` | данных карточки недостаточно, чтобы решить |

Порядок решения:

1. Проверь коды отказа из таблицы сверху вниз. Первый подходящий — твой ответ.
2. Если ни один не подходит и выполнены все четыре условия — ставь `R`.
3. Если не можешь решить — ставь `U`.

Оценивай каждую карточку отдельно, независимо от остальных и от порядка в файле. `card_id` ничего не говорит о качестве карточки.

Формат CSV: кодировка UTF-8, разделитель — запятая, `comment` в двойных кавычках. Первая строка — заголовок:

```
card_id,label,comment
```

`comment` — одно предложение до 200 символов о том, почему выбран этот код. Для `R` укажи, какая это технология и по какому признаку видно, что стадия ранняя.

## Проверка перед отправкой

- В `synonyms.jsonl` столько строк, сколько сигналов в `experts.csv`. Каждый `row_id` встречается ровно один раз, каждая строка — валидный JSON.
- В `labels.csv` (без заголовка) столько строк, сколько карточек в `cards.csv`. Каждый `label` — один из девяти кодов (`R`, `N-NOI`, `N-OFF`, `N-FUND`, `N-OVR`, `N-GEN`, `N-MAT`, `N-HYP`, `U`), латиницей и через дефис, как в таблице.
- Последней строкой ответа, вне файлов, напиши:

```
Сигналов: N; строк synonyms: N. Карточек: M; строк labels: M.
```
