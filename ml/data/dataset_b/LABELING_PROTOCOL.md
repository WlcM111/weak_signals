# Протокол разметки датасета B

## Единица разметки
Кандидат живого прогона (или наблюдение веб-поиска) в контексте темы: название кластера, свидетельства (название, URL, тип и доверие источника, дата) и тема запроса. Дубликаты (общий канонический URL или название внутри темы) объединяются в группу; размечается группа, в датасет попадает представитель (последнее наблюдение).

## Рубрика (согласована с примерами организаторов)
Позитив `WEAK_SIGNAL_RELEVANT` — все условия сразу:
1. **Релевантность теме запроса** — кандидат относится к теме, а не к соседней области.
2. **Конкретность** — конкретная технология, метод, продукт, практика или комбинация, а не общая категория.
3. **Ранняя стадия** — исследование, прототип, пилот, первые внедрения, нишевый открытый код, зарождающаяся инфраструктура; не массовое применение.
4. **Проверяемое свидетельство** — источник с датой, из которого видно, что именно наблюдается и когда.

Сложные негативы (метка 0, вид указывается): `OFF_TOPIC` — не по теме; `GENERIC_CONCEPT` — общее понятие; `OVERVIEW` — обзор, список, подборка; `MATURE` — массовая или устоявшаяся технология; `NOISE` — склейка разнородных документов, служебный текст, пустое название; `HYPE` — заявления без проверяемого содержания; `ROUTINE_FUNDING` — рядовая новость о финансировании без технологического содержания. `UNCERTAIN` (метка null) — свидетельств недостаточно для решения; такие строки не обучают и не оценивают.

## Процесс
1. Сборка кандидатов из журналов (`runs_parser.py`), группировка (`grouping.py`).
2. Silver-метка группы: вид, уверенность (high/medium/low), обоснование со ссылкой на свидетельства (`labels_silver_v1.jsonl`). Аннотатор — `claude-opus-5.5`, метод `llm_assisted_silver`.
3. Веб-наблюдения — только из результатов поиска с датой публикации (`web_observations_v1.jsonl`).
4. Сборка и валидация (`build.py`): поля, URL, `published_at ≤ evidence_as_of`, группа в одном split.
5. **Экспертная проверка (ожидается):** два эксперта независимо по этой рубрике; согласие — каппа Коэна; расхождения — арбитраж третьим экспертом; метки с изменённым решением получают `review_status: reviewed` и новую версию датасета. До этого статус всех меток — `pending_human_review`.

## Правила против утечек
Обоснование метки, вид метки и производственный score не являются признаками (тест). Holdout-темы выбраны до обучения и не меняются. Строки организаторов и их тексты в B не копируются.
