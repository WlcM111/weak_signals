# Протокол оценки A → B

Версия 1 от 2026-09-24. Правила закреплены в коде до финальной оценки: `ml/src/ml/seq/experiments.py` (сетки `GRID`, `FORGETTING_TOLERANCE`, `Runner._acceptance`) и `ml/src/ml/dataset_b/build.py` (`HOLDOUT_TOPICS`, тематические фолды). Изменение правил = новая версия протокола и новый прогон.

## Данные и разбиения

**A** — `ml/data/labels/dataset_ds-2026.09.19-v2.jsonl`, 225 строк: 100 позитивов организаторов (`gpb_dataset_2026_09`) и 125 негативов команды (`team_negatives_v1`, один аннотатор). Отдельного файла негативов от организаторов в материалах нет, поэтому вспомогательные негативы помечены происхождением и хранятся в манифесте Stage A. В признаки идёт только название: описание позитива — колонка «Почему это слабый сигнал», то есть объяснение метки. Split групповой, стратифицирован по (метка, домен), seed 20260915, доли 70/15/15; почти-дубликаты названий (Жаккар токенов ≥ 0,6) объединяются в группу. Строки A, связанные с B (общий канонический URL или Жаккар названий ≥ 0,5), исключаются из A-train.

**B** — `ml/data/dataset_b/dataset_b_v1.jsonl`. Holdout — три темы целиком: «квантовые сенсоры для навигации», «перспективные решения в финтехе», «цифровые двойники в энергетике». Остальные 15 тем — пять dev-фолдов по темам со сбалансированным числом позитивов. Группа кандидата (общий URL или название в теме) целиком в одном split. Строки `UNCERTAIN` лежат отдельно и не участвуют ни в обучении, ни в метриках.

**Роли выборок.** A-train — обучение Stage A и единственный источник replay. A-dev — измерение забывания и выбор λ_A не использует (λ_A выбирается групповой CV внутри A-train). A-test и B-holdout — только финальная однократная оценка.

## Метрики

Основная для выбора — PR-AUC (average precision) по объединённым внефолдовым оценкам dev B. Дополнительно: ROC-AUC; P@3 и P@5 по темам (учитываются темы с ≥ k кандидатами, число тем указывается); nDCG@5 (темы с хотя бы одним позитивом); Brier и ECE (5 равных интервалов) после калибровки Платта на dev-OOF; precision/recall/F1 при пороге максимума F1 на dev.

Неопределённость: dev — бутстрэп по темам (1000 перевыборок); holdout — бутстрэп по группам (три темы — слишком мало для перевыборки тем). Сравнение с производственной системой — парные разности на одних и тех же перевыборках, только по живым строкам, где производственный score записан в журнале прогона.

Базовые линии: производственный score из журналов; e5-близость кластера к запросу из журналов; признаки близости v2 по отдельности; Stage A без B (zero-shot); гибрид Stage A + e5-близость без обучения на B (равные веса z-оценок); константа; перестановка оценок внутри темы (200 перестановок).

## Варианты и сетки

| Вариант | Что это | Сетка |
|---|---|---|
| `stage_a` | только A | λ_A ∈ {0,3; 1; 3; 10} групповой CV на A-train |
| `b_only` | только B с нуля | λ ∈ {1; 3; 10; 30} |
| `seq_finetune_early` | от θ_A, 5 итераций, без защиты | λ = 3 |
| `seq_finetune` | от θ_A до сходимости, без защиты | λ = 3 |
| `seq_l2sp` | штраф λ_sp‖θ − θ_A‖² | λ_sp ∈ {1; 3; 10; 30} |
| `seq_laplace` | штраф α(θ − θ_A)ᵀH_A(θ − θ_A) (Лаплас/EWC, полный гессиан) | α ∈ {0,3; 1; 3; 10} |
| `seq_laplace_replay` | Лаплас + replay A-train с весом ρ | α ∈ {0,3; 1; 3} × ρ ∈ {0,3; 1} |
| `joint` | совместное обучение A-train + B с нуля | λ ∈ {3; 10} × w_A ∈ {0,3; 1} |

## Выбор

1. Для каждого варианта — лучший набор гиперпараметров по dev PR-AUC.
2. Допуск забывания: ROC-AUC на A-dev после Stage B ≥ ROC-AUC Stage A − 0,05. Варианты вне допуска не выбираются.
3. Среди допустимых — максимум dev PR-AUC; при равенстве — вариант с защитой знаний A. Отдельно фиксируется лучший последовательный вариант (`seq_*`) — он рекомендуется для режима A → B.

## Приёмка (замена активной модели)

Кандидат может стать активной моделью, только если одновременно выполнено:

1. нижняя граница 95 % ДИ парной разности dev PR-AUC «кандидат − производственный score» > 0;
2. забывание A в допуске;
3. на holdout парная разность PR-AUC с производственным score ≥ −0,05 (однократная оценка);
4. артефакт обучен на производственном эмбеддере (`intfloat/...`), а не на хеширующей заглушке.

Иначе решение `reject_keep_current_model`, и `seq-export --activate` откажет в активации (версия экспортируется без активации).

## Однократность holdout

Каждое вычисление метрик на holdout дописывается в `<reports>/experiments/holdout_usage.jsonl`. Подбор после просмотра holdout запрещён. Если holdout использован повторно, это указывается в отчёте, и оценка перестаёт считаться независимой.

## Отступления в этой сессии (контейнер, хеширующий эмбеддер)

Holdout B вычислялся трижды: smoke-прогон, первый полный прогон и повтор после расширения сеток и добавления блока приёмки. Сетки расширялись из-за признаков переобучения на dev, но holdout к этому моменту уже был виден, поэтому holdout этой сессии **не является независимой оценкой**. Записи о первых двух вычислениях восстановлены вручную в `holdout_usage.jsonl`. На Mac первый прогон `seq-experiments --embedder e5` даёт чистую оценку, если до него holdout не вычислялся на e5.
