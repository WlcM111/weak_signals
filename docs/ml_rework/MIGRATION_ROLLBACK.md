# Миграция и откат

**Схема БД не меняется** (миграций нет). Меняются код сервисов, образ trainer, содержимое тома `model-store` (новая версия и, при приёмке, `active`) и две переменные окружения.

## Перед применением
1. Резервная копия тома моделей: см. RUNBOOK_MACOS.md, разд. 2 (tar тома `*_model-store`).
2. Дамп БД: `pg_dump` (разд. 2) — на случай отката данных прогонов.
3. Проверка, применён ли прошлый `ml_rework.patch`, и его откат (разд. 3).

## Применение
`git apply --check` → `git apply` → пересборка `analyzer`, `orchestrator-*`, `collector`, `trainer` → тесты → эксперименты → экспорт. Активная модель **не меняется**, пока приёмка не дала `accept`.

## Совместимость
- Артефакты v1 загружаются как раньше; v2 выбирается по `feature_schema_version` манифеста.
- `WS_CANDIDATE_JUDGE_ORDER=ml` меняет порядок выдачи при включённой смысловой проверке (раньше порядок задавала LLM). Для прежнего поведения — `llm`.
- Опоздавшие задания теперь завершаются `DEADLINE_EXCEEDED` вместо частичной выдачи после срока.
- 406 от arXiv в статистике источников — `HTTP_4XX` вместо `RATE_LIMITED`.

## Откат (от быстрого к полному)
1. Порядок выдачи: `WS_CANDIDATE_JUDGE_ORDER=llm` в `.env`, `docker compose up -d orchestrator-api orchestrator-worker`.
2. Модель: `docker compose --profile ml run --rm trainer seq-activate <прежняя_версия>` и `docker compose restart analyzer`; либо восстановить том из tar (разд. 2).
3. Код: `git apply -R weak-signals-ml-rework.patch` (сначала `--check`), пересборка образов.
4. Данные БД: восстановление из дампа (только если нужно откатить результаты прогонов).
