## Подтверждённые причины нерелевантной выдачи

1. **Экстраполяция по коллинеарным эмбеддинговым признакам.** В `analytics-20260924-003901.txt` вклад `emb_sim_mature` 0,865 → +8,77 и 0,868 → +7,55, `emb_sim_weak` 0,876 → −4,62: наклон ≈ ±410 логитов на единицу косинуса вокруг точки ≈ 0,887 (среднее обучения). Центроиды живых кластеров лежат ниже обеих точек, знаки вкладов переворачиваются, и офтоп получает высокий score (микропластик — 99,8 %).
2. **Утечка объяснения метки.** Текст позитива — колонка «Почему это слабый сигнал»; классы разделяются стилем: TF-IDF F1 0,859, длина описания 0,907. Новое: даже длина **названия** даёт ROC-AUC 0,901 на A-dev и 0,901 на A-test (позитивы называли методологи, негативы — команда).
3. **Несовпадение признаков обучения и выполнения.** Обогащено 0 из 225 строк: 14 коллекционных/энциклопедических признаков в обучении константны; счётные признаки на выполнении считаются по склейке кластера (org_mentions 11–12). Единица обучения (описание) ≠ единица решения (кластер документов).
4. **ML почти не влияет на выдачу.** Ранжирование по score; при включённой смысловой оценке `apply_judgement` переупорядочивал по релевантности LLM.
5. **Срок 1200 с не сквозной.** Анализ «сроком не ограничивался», расширение запроса — без предела; опоздавшее задание продолжало работу.
6. **Holdout изношен.** 45 строк использованы ≥ 6 раз (`ml/reports/runs.jsonl`); внефолдовые оценки калибратора перезаписываются при 5×5 CV.
7. **HTTP.** `Retry-After` разбирался только в секундах (HTTP-дата игнорировалась); внутренние повторы до 8 с выполнялись даже при `Retry-After: 60`; 406 от arXiv переименовывался в RATE_LIMITED без установленной причины.
8. **Производственный score на размеченных живых кандидатах не имеет сигнала:** dev B (113 живых строк, 16 позитивов) PR-AUC 0,156 при доле позитивов 0,142–0,156, ROC-AUC 0,515; e5-близость к запросу из тех же журналов — PR-AUC 0,203, ROC-AUC 0,628.
