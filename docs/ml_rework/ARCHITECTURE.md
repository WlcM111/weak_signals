# Архитектура после переработки ML (ADR-ML-2026-09-24)

## Поток запроса и место решения модели

```
запрос ─► orchestrator.expand: LLM-расширение запроса, предел 60 с; при таймауте/ошибке — глоссарий
       ─► collector: сбор документов (лимиты источников, Retry-After в секундах и датой, паузы)
       ─► analyzer.RunAnalysis:
             e5-эмбеддинги → кластеры → кандидат = кластер + до 8 свидетельств
             признаки v1 (правила MATURE/HYPE/OFF_TOPIC, карточки) + признаки v2 (тема × название × свидетельства)
             ► LinearV2Classifier.predict_proba → калиброванный score        ◄── РЕШЕНИЕ ЛОКАЛЬНОЙ МОДЕЛИ
             правила исключения + порог → WEAK_SIGNAL / MATURE / HYPE / OFF_TOPIC / …; ранг = порядок score
       ─► orchestrator.narrate: смысловая проверка LLM только исключает (WS_CANDIDATE_JUDGE_ORDER=ml),
             порядок выдачи остаётся порядком модели; нарративы карточек (insight) — по выбранным кандидатам
       ─► результат в PostgreSQL до истечения 1200 с (или честный отказ/частичный результат)
```

## Решения

**ADR-1. Признаки v2 вместо центроидов.** Центроиды «слабое/зрелое» давали экстраполяцию с наклоном ±410 логитов на единицу косинуса. v2 (`services/analyzer/src/analyzer/domain/features_v2.py`, 37 признаков, реестр `schemas/feature_registry_v2.json`): relevance (близость темы к названию и свидетельствам, e5-близость кластера к запросу `rel_cluster_query_v1`, доли терминов темы с глоссарием ru→en), specificity (длина и связность, обзорность, пересечение с темой), lexical (доли документов с маркерами зрелости/хайпа/стадий по тем же словарям, что v1), metadata (типы и доверие источников, свежесть, разнообразие), embedding (8 компонент PCA названий A-train, заморожены на Stage A). Признаки, зависящие от темы и свидетельств (`TOPIC_DEPENDENT`), равны 0 в режиме описания (строки A, `ScoreText`).

**ADR-2. Единица обучения = единица решения.** B размечен на уровне кандидата живого прогона (название кластера + свидетельства + тема), а не описаний. Один и тот же код `observation_features` считает признаки в `ml` и в `analyzer`; паритет проверяет тест `RuntimeParityTest`.

**ADR-3. Последовательное обучение A → B.** Модель — логистическая регрессия (L-BFGS, точный гессиан; `ml/src/ml/seq/linear.py`).
- Stage A: A-train (позитивы организаторов + явно помеченные негативы команды), только названия; стандартизация признаков A по A-train замораживается; λ_A — групповой CV; сохраняются θ_A и гессиан H_A.
- Stage B: старт из θ_A; стандартизация признаков темы добавляется по B-train (признаки A не трогаются); цель — потеря на B + якорь: Лаплас/EWC `α(θ−θ_A)ᵀH_A(θ−θ_A)` или L2-SP `λ‖θ−θ_A‖²`, опционально replay только A-train. H_A пересчитывается в пространстве Stage B и сверяется с сохранённым (совпадение до 1e-8 — тест).
- Контрольные точки JSON с происхождением: `parent_id`, `parent_sha256`, `started_from`, `distance_from_parent`, `replay_ids`, хеши данных (`ml/src/ml/seq/stages.py`).

**ADR-4. Артефакт v2.** `model_v2.json` (веса в пространстве исходных признаков — стандартизация свёрнута; калибровка Платта; порог; проекция PCA; глоссарий; происхождение), `rules.json`, `manifest.json` с SHA-256. Без pickle. Загрузчик сверяет суммы, состав признаков, число компонент проекции и эмбеддер. v1 продолжает загружаться.

**ADR-5. Роль LLM.** (1) Расширение запроса — влияет на сбор и на признак `rel_cluster_query_v1`; (2) смысловая проверка кандидатов — только исключение явного офтопа/обзоров, порядок задаёт ML; (3) нарративы карточек с проверкой опоры на источники (insight, без изменений). Итоговый балл LLM не является мерой качества системы.

**ADR-6. Сквозной срок 1200 с.** Задание с истёкшим сроком (очередь съела бюджет) завершается `DEADLINE_EXCEEDED` сразу; расширение ≤ 60 с; анализ ограничен остатком срока с резервом 60 с и отменяется в analyzer по таймауту; повтор после сбоя — только если до срока остаётся ≥ 300 с.

**ADR-7. HTTP.** `Retry-After` — секунды и HTTP-дата; при паузе > 8 с клиент не повторяет сам (решает лимитер источника), суммарный сон повторов ≤ 15 с, каждая попытка считается и пишется в журнал; 406 от arXiv — `HTTP_4XX` «причина не установлена», пауза сохраняется.

**ADR-8. Приёмка и активация.** `seq-experiments` вычисляет решение приёмки по заранее заданным правилам (PROTOCOL.md). `seq-export --activate` активирует версию только при `accept`; прежний `active` копируется в `rollback/active-<время>`; `seq-activate <версия>` — откат.
