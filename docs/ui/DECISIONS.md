# Журнал решений и противоречий — сервис ui

Обозначения: **C-U** — противоречие комплекта, **D-U** — решение реализации.

## Противоречия

### C-U1. Streamlit в задании против React в ТЗ

`HANDOFF_UI.md` предписывает Streamlit и прямо запрещает React (§23). ТЗ заказчика (§3.2) задаёт
обратный приоритет: «Интерфейс (UI): web-приложение (фреймворки React для frontend;
FastAPI/Django для backend). Допустим базовый UI на Streamlit» — React назван основным
вариантом, Streamlit помечен как допустимый базовый.

**Решение.** Реализован React: ТЗ заказчика выше внутреннего задания на исполнителя, а §8.2 и
§7.2 ТЗ оценивают демонстрационный стенд как полноценное web-приложение. Все функциональные
требования `HANDOFF_UI` (§7 страницы 1–5, §14 сообщения об ошибках, §15 идемпотентность и
опрос, §17 безопасность, §20 критерии приёмки) выполнены без изменений — изменился только
способ отображения. Требования §6 (структура `app.py`/`api_client.py`/`formatting.py`) перенесены
по смыслу: `src/App.tsx`, `src/api/client.ts`, `src/lib/format.ts`.

### C-U2. `compose.yaml` запускает Streamlit

Нормативный `compose.yaml` задаёт сервису `ui` `entrypoint: ["streamlit", ...]` и healthcheck по
`/_stcore/health`.

**Решение.** В `compose.yaml` изменён только блок `ui`: убран `entrypoint` (образ сам запускает
nginx), healthcheck переведён на `/healthz`, который отдаёт nginx. Порт 8501, имя сервиса, сети
и зависимость от `orchestrator-api` сохранены — остальная документация и ссылки остаются верными.
Изменение зафиксировано в `CHANGELOG_CONTRACTS.md`.

## Решения реализации

### D-U1. Прокси вместо запросов из браузера

Фронтенд обращается к относительному `/api/...`, а nginx проксирует запросы на
`orchestrator-api`, подставляя `X-API-Key` и `X-Correlation-Id`. Это решает три задачи сразу:
браузер не получает API-ключ (§17 HANDOFF_UI), нет CORS-настроек на стороне orchestrator, а
адрес API меняется переменной окружения без пересборки образа.

### D-U2. TanStack Query для опроса и прогрессивной выдачи

Требование §20.2 — элементы появляются во время `NARRATING` без ручной перезагрузки. Опрос
задания и результата описан декларативно: `refetchInterval` выключается, как только статус
становится терминальным. Это надёжнее самодельных таймеров и не оставляет висящих интервалов
при переходе между страницами.

### D-U3. Собственная дизайн-система вместо CSS-фреймворка

Стили написаны на CSS с переменными и слоями (`@layer`), без Tailwind и UI-китов. Причины: одна
зависимость меньше в сборке, полный контроль над типографикой и тёмной/светлой темой, отсутствие
классов-«простыней» в разметке. Компоненты состояний (скелетоны, пустые состояния, баннеры)
реализованы в `src/components/ui.tsx`.

### D-U4. Переводы значений перечислений в одном месте

`src/lib/format.ts` содержит все словари (статусы, решения, причины, типы источников, уровни
доверенности, виды резюме, направления признаков) и функции форматирования. Неизвестное значение
перечисления показывается как есть и не роняет страницу (§13 HANDOFF_UI).

### D-U5. Отчёт Markdown собирается на клиенте

Кнопка «Скачать отчёт» формирует Markdown из уже загруженного инсайта (`src/lib/report.ts`) и
отдаёт его через `Blob` — без обращения к серверу и без временных файлов. Разделы отчёта
совпадают с разделами страницы, это проверяет `tools/check_ui_conformance.py`.

### D-U6. Проверка интерфейса статическим анализом

Собрать фронтенд в среде без доступа к реестру npm нельзя, поэтому добавлен
`tools/check_ui_conformance.py`: сверяет вызовы клиента с путями OpenAPI, разрешает импорты,
проверяет наличие обязательных полей источника и разделов инсайта, отсутствие вставок сырого
HTML и русскость текстов интерфейса. Проверка покрывает ровно те требования, которые иначе
проверялись бы глазами при ручном прогоне.

### D-U7. `npm install` вместо `npm ci`

Lock-файл не коммитится (сгенерировать его без доступа к реестру невозможно), поэтому версии
зафиксированы точными значениями в `package.json`, а образ собирается через `npm install`. После
первой сборки в рабочем контуре рекомендуется закоммитить `package-lock.json` и перейти на
`npm ci` — это ускорит сборку и сделает её полностью воспроизводимой.

## Доработка UX/UI, версия 1.3.0 (2026-10-15)

Основание — разбор интерфейса на отрисованных страницах (ПК 1366–1920 px, планшет, телефон, обе
темы) и выбор владельца по вариантам: результаты — вариант А, цвет — вариант Б, инсайт и
исключённые — вариант Б, стартовый экран — все изменения, кроме формы поиска на главной.
Спецификация для разработки — `docs/ui/UX_HANDOFF.md`.

### D-U8. Результаты: сначала выдача

Порядок в разметке: шапка → выдача → сводка. На ПК раскладка прежняя (сводка справа задана
областями сетки), а на узком экране список сигналов теперь на первом экране — раньше его
опускали ниже края сводка и спектр. Порядок чтения диктором совпадает с экраном. Под заголовком
одной строкой — дата, длительность, «N в выдаче · M кандидатов». Пока задание идёт, статус
показывает только полоса хода: плашка в шапке и состояние в «Ходе задания» скрыты, чтобы один
статус не повторялся трижды. Для завершённого задания без сигналов — «Слабые сигналы не найдены».

### D-U9. Кнопка инсайта в шапке карточки сигнала

На 1366 и 1440 px кнопка «Открыть инсайт» внизу карточки была ниже края. Теперь она в шапке
рядом с названием; в разделённом режиме шапка закреплена при прокрутке карточки.

### D-U10. Подписи совпадают с числами

- «Обработано источников» показывает `sources_processed`, в подсказке — запросы и документы
  (раньше крупным числом выводились запросы — `http_requests_total`).
- «Кандидатов на слабый сигнал»: «признаны: N, в выдаче после проверки: M».
- Шкала карточки названа «индекс уверенности» и снабжена пояснением: число на шкале и
  вероятность в тексте объяснения из бэкенда различаются.
- Признаки-основы `sc_*` показываются как «протот…», полная подпись — во всплывающей подсказке;
  у остальных признаков шкалы в скобках уходят в подсказку.
- Название технологии и оригинал в скобках выводятся раздельно (`splitTitle`).

### D-U11. Исключённые кандидаты: фильтр и компактный список

Таблица с длинными объяснениями заменена фильтром по решению (с количеством) и списком: одна
строка на кандидата, объяснение раскрывается в строке. На узкой области строка перестраивается
в три ряда, плашка решения больше не наезжает на соседний текст.

### D-U12. Цвет и шрифт: один смысл — один цвет

- Уровни уверенности модели и доверенности источника: высокий — зелёный, средний — нейтральный,
  низкий — пунктирная рамка; три деления шкалы повторяют уровень не только цветом. Жёлтый
  остаётся за «зрелостью», бирюзовый — за «слабым сигналом». Легенда в «Методологии» приведена
  к тем же цветам.
- Вторичный текст не мельче 13 px (`max(13px, …)`); исключение — подписи нижнего меню телефона и
  узкой боковой панели (12 px, иначе «Методология» не помещается на 320 px).
- Длинные названия технологий — Lato Bold вместо декоративного Jura.
- В светлой теме сводки (результаты, метрики модели, карточка инсайта, шаги методологии) —
  светлые панели с фиолетовой полосой; тёмным остаётся только прибор с полем сигналов. В тёмной
  теме панели прежние. Жёсткие `#fff` и цвета прибора внутри панелей заменены токенами.
- `--signal-ink` в светлой теме `#066c7d`: адрес источника на подсвеченной карточке давал
  4,4 : 1, теперь 5,2 : 1.

### D-U13. Инсайт: документ с полосой разделов и колонкой источников

Шапка во всю ширину (название, оригинал, индекс, стадия и тренд подписанными значениями),
разделы — полосой над текстом (на телефоне листается вбок), источники при ширине области от
70rem — колонкой справа. Главная кнопка «Скачать отчёт (Markdown)» заменена меню «Экспорт»:
«Печать или PDF» и «Markdown (.md)»; меню закрывается по Escape, щелчку снаружи и после выбора.
Служебные ссылки модели «(документ d5)», «[doc:2]» убираются из текста страницы и отчёта
(`cleanRefs`). Резюме в «Оценках» сокращены до двух строк — полный текст в источниках, фрагмент
оригинала источника свёрнут. Стили печати: только документ, тёмный текст, адреса ссылок.

### D-U14. Форма запроса

Ползунок «Размер выдачи» 1…50 заменён кнопками ТОП-5, 10, 15, 25, 50 (радиокнопки, стрелки
работают). Кнопка «Найти» всегда активна: при пустом поле — сообщение под полем, поле помечено
`aria-invalid`, фокус возвращается в поле. Подсказка клавиш — ⌘ или Ctrl по платформе. На
телефоне примеры — лентой, чтобы форма с кнопкой помещалась на первый экран; на коротком экране
кнопка закреплена над нижним меню (тень — только когда полоса действительно закреплена).
Форма вынесена в `components/QueryForm.tsx`. Форма поиска на главной не добавлялась — по решению
владельца для этого есть раздел «Запрос».

### D-U15. Доступность (WCAG 2.1 AA)

- 2.2.2: кнопка «Пауза анимации» в панели навигации останавливает бесконечные анимации
  (атрибут `data-motion-paused` на корне, выбор — в `localStorage` в try/catch); пинг «API на
  связи» — два импульса, мигание «API недоступен» — четыре.
- 2.4.1: ссылка «К содержанию» видна при фокусе, переводит фокус в `main` без смены адреса.
- 3.1.2: `lang` у иноязычных названий и фрагментов источников (из `language_code`), у
  оригинальных названий и латинских названий кандидатов.
- 1.3.1: заголовки источников — `h3`; шапка инсайта — `header`, а не `aside`.
- 2.5.5: на сенсорных экранах элементы управления не меньше 44 px.
- 1.4.4: базовый размер шрифта задан от размера шрифта браузера (`93.75%`, в режиме приложения
  `clamp()` в rem), настройка «крупный шрифт» работает.
- 1.4.10: на телефоне вкладки результатов подписаны коротко; полная подпись остаётся для
  диктора.

### D-U16. Тексты

На главной — «из открытых источников» без числа (было «из восьми», в «Методологии» — «из
девяти»); в «Методологии» отмечено, что GDELT по умолчанию выключен. «Модель analyzer» —
«модель ранжирования (analyzer)». Баннер «API недоступен» объясняет последствия простыми
словами, команда `docker compose ps` — мелким текстом для администратора. Имя файла отчёта —
латиницей (транслитерация), как и обещал комментарий в коде.

### D-U17. Что требует решения в бэкенде

Интерфейс эти места только смягчает:

1. Текст объяснения решения называет вероятность классификатора (например, 64 %), а шкала —
   индекс уверенности (82 %). Лучше писать в тексте то же число или оба с подписями.
2. Для признаков `sc_*` отдавать полное слово из профиля, а не основу.
3. Дроби в объяснениях — в процентах или с запятой, как в интерфейсе («0.28» → «28 %»).
