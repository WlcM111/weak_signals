# Протокол сопоставления с экспертным списком match-v1

Этап 2 плана доработки (аудит A4). Протокол фиксируется **до** оценки прогонов и не меняется по их результатам.
Инструмент — `python -m ml.benchmark match`, `match-score`, `synonyms-template`.

## Единицы и знаменатель

- **Экспертный сигнал** — строка `label = 1` датасета организаторов (`ml/data/labels/dataset_ds-2026.09.19-v2.jsonl`).
- **Тема** — `domain_tag` сигнала; соответствие тем и запросов кейса — `ml.hit_rate.DOMAIN_QUERY`.
- **Знаменатель** — число экспертных сигналов темы. Задание по теме вне кейса получает пометку «экспертного списка
  нет» и в полноту не входит.

## Этапы, на которых ищется сигнал

| Этап | Объекты |
|---|---|
| `found` | документы, выданные адаптерами, включая дубли, отбракованные и отсечённые лимитом источника |
| `collected` | документы коллекции |
| `relevant` | документы после почти-дублей и порога близости к запросу |
| `clustered` | документы в выбранных кластерах (будущих кандидатах) |
| `pool` | кандидаты в пуле рубрики (текст — название, ключевые фразы, термин и профиль из рубрики) |
| `judged` | кандидаты, признанные рубрикой (R) или добранные (U) |
| `finalized` | кандидаты с доведённой карточкой, не снятые правилом обзоров и финальной проверкой |
| `shown` | карточки выдачи (название и описание, источники) |

## Правила совпадения

1. **По ссылке (`link`), автоматически.** Совпадает адрес из `source_urls` сигнала с адресом или DOI документа
   объекта, после нормализации: без схемы, `www`, параметров и якоря. Отдельно сравниваются DOI и идентификатор arXiv,
   в том числе `10.48550/arXiv.*`.
2. **По термину (`term`), спорное.** Нормализованное название сигнала или термин в скобках входит в нормализованный
   текст объекта целыми словами. Нормализация: нижний регистр, «ё» → «е», всё, кроме букв и цифр, — пробел.
   Термины короче 5 символов не используются.
3. **По синониму (`synonym`), спорное.** Термин из файла синонимов. Файл создаётся командой `synonyms-template`,
   заполняется людьми до оценки и не меняется по её результатам. SHA-256 файла записывается в `matches.json`.

## Проверка людьми

- Все совпадения `term` и `synonym` выгружаются парами «сигнал — объект» в два одинаковых листа: `reviewer_1.csv`
  и `reviewer_2.csv`.
- Два человека независимо ставят `Y` (совпадает), `N` (нет) или `U` (нельзя решить).
- Согласие — каппа Коэна по парам, где оба ответили `Y` или `N`, с 95 % интервалом бутстрэпом по парам.
- Разногласия и неразмеченные пары попадают в `disagreements.csv`. Решение третьего человека или итог обсуждения
  записывается в `resolution.csv` с колонками `pair_id` и `decision`.
- Засчитываются только `link`, пары с `Y` у обоих и пары с `Y` в `resolution.csv`. Неразрешённые пары не
  засчитываются, поэтому полнота до разрешения разногласий — нижняя граница.

## Метрики

- **Полнота по этапу** для задания — доля экспертных сигналов темы, у которых есть подтверждённое совпадение с
  объектом этапа. Сводная оценка — среднее по темам с 95 % интервалом бутстрэпом по темам.
- **Первый этап потери** сигнала — первый этап, на котором подтверждённого совпадения уже нет.
- **Сравнение двух вариантов** — парное, по общим темам: `python -m ml.benchmark compare A B --metric recall.shown`.
- **precision@K по ручной разметке двумя людьми** — `tools/quality/human_eval.py score --k 3 5 10`: по темам, по
  согласованным карточкам, с интервалом бутстрэпом по темам.

## Ограничения

- В датасете нет дат публикаций, а `source_urls` есть не у всех сигналов. Многие совпадения возможны только по
  терминам и требуют проверки людьми.
- Шесть тем кейса — данные для настройки (dev). Новые темы и период для независимой проверки — этап 4.
