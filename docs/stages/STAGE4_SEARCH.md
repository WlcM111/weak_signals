# Этап 4. Поиск «от темы к технологиям»

## 1. Почему система не находила экспертные сигналы — факты

| Факт | Источник данных |
|---|---|
| Ни одна из 285 ссылок организаторов не попала в собранные документы; одна мелькнула в сыром ответе | 18 снимков стенда, 5 748 документов, 96 МБ ответов |
| Запросы к источникам — пересказ темы: «edge security», «AI security systems», «data storage systems for AI», «blockchain payment systems» | `raw_responses` снимков этапа 3 |
| arXiv отдаёт 50 самых новых работ, Semantic Scholar — самые новые, GitHub — самые популярные | те же ответы |
| RSS-ленты хранят 1–7 дней, статьи экспертов старше на месяцы | даты записей лент |
| Даже точными названиями технологий адаптеры находили 37 из 100. И всех слов фразы: arXiv — 0 документов в 29 случаях, Semantic Scholar — в 21. GitHub — 22 отказа по частоте | `expert_retrieval.csv` |
| Сеть: без VPN Semantic Scholar отвечает 403, SiliconANGLE и EU-Startups недоступны. Через VPN США доступно всё, кроме Tech Funding News | `netcheck-novpn.json`, `netcheck-usa.json` |
| Условия использования TechCrunch запрещают автоматическое извлечение данных — архив изданий не подключался | techcrunch.com/terms-of-service |

## 2. Что сделано

| № | Пункт плана | Реализация |
|---|---|---|
| 1 | Технологии вместо пересказа темы | insight `expand_v2`: 20–40 конкретных ранних технологий (англ. названия). collector `technology_mining`: названия из заголовков широкого прохода — частота по документам и источникам, длина, поглощение вложенных, отсев общих и слишком частых. Без LLM |
| 2 | Прицельный поиск, экспертный список не используется | `search_targeted`: arXiv (точная фраза, иначе все слова), Semantic Scholar (`/paper/search`), OpenAlex (`search`), GitHub (best match, первые 20 технологий), Hacker News |
| 3 | Релевантность в окне дат | Все прицельные запросы — по релевантности, публикации за 24 месяца (`WS_COLLECTOR_TARGETED_WINDOW_MONTHS`) |
| 4 | История новостей | GDELT не менялся — маршрут настраивается отдельно. Архивы изданий не подключались: TechCrunch запрещает автоматическое извлечение. Добавлены RSS-ленты SiliconANGLE, EU-Startups, EE Times, Robotics & Automation News, PR Newswire, The Block |
| 5 | Квоты на технологию | По 3 документа на технологию в каждом источнике. Широкий проход — 60 на источник, RSS — без изменений. 300 мест общего лимита — прицельному проходу |
| 6 | Пул 80 и одиночные кластеры | `WS_RUBRIC_POOL=80`. analyzer `singleton_candidates`: ближайшие к запросу одиночные документы — кандидаты, не больше четверти пула |
| 7 | Быстрый замер | `tools/benchmark/strategy_check.py`: шесть тем без оценки моделью и без разметки. Широкий проход против широкого с прицельным |

## 3. Приёмка

1. **Быстрый замер.** Доля экспертных технологий в собранном с прицельным проходом выше, чем широким проходом
   того же замера.
2. **Полный прогон.** Подтверждённая полнота по экспертам выше этапа 3.1, precision@5 не ниже этапа 3 (0,75).
   Найденное вне экспертного списка засчитывается по разметке выдачи, а не отбрасывается.

## 4. Этап 4.2: по быстрому замеру и диагностике API (07.10.2026)

### Факты

| Факт | Данные |
|---|---|
| Быстрый замер: 6 из 100 широким проходом, 8 из 100 с прицельным | `strategy_check.json` |
| arXiv: 429 в первой же теме — пауза 30 минут на весь замер | вывод замера |
| GitHub: 403 во всех темах. В контейнере нет `WS_GITHUB_TOKEN`, квота поиска 10 в минуту, а каталог задавал 24 в минуту | диагностика API: `x-ratelimit-limit: 10` |
| Semantic Scholar: три 429 подряд в каждой теме. Анонимный пул общий для всех; bulk проходил в соседних средах | диагностика API |
| PR Newswire: без `Accept` — 301 на адрес со слешем и 404, с `Accept` — сразу 200 | диагностика API, rss_31 |
| Лимитер: первые запросы почти одновременно (ёмкость `rate × 5`); пауза после 429 останавливала только одну задачу; повторы HTTP-клиента шли мимо лимитера | аудит кода |
| Технологии модели: у 44 из 226 в конце слово-категория, много зрелых тем. Извлечённые: «show hn», «ai agents», «de la», обрывки | вывод замера |
| В примерах промпта `expand_v2` стояли названия, совпадающие с экспертными сигналами — оценка была бы нечестной | сверка с датасетом |

### Изменения

См. `docs/collector/DECISIONS.md`, раздел «Этап 4.2». Дополнительно:
- **insight `expand_v3`:**
  - 25–40 конкретных подходов, протоколов и классов продуктов, появившихся в 2024–2026 годах;
  - примеры — только из других областей;
  - явный запрет слов-категорий, зрелых тем и рекламных определений;
  - тот же фильтр применяется к ответу модели.
- **Извлечение технологий:**
  - заголовки режутся по знакам препинания;
  - префиксы Hacker News отбрасываются;
  - общие словосочетания и неанглийские слова отсеиваются;
  - нужен повтор в двух разных источниках;
  - единственное и множественное число склеиваются.

### Что не исправить кодом

- **GDELT** ограничивает адрес на стороне сервера. Запросы к нему не менялись: маршрут настраивается отдельно.
- **Semantic Scholar без ключа** работает в общем анонимном пуле. Ключ даёт собственную квоту 1 запрос в секунду.
- **GitHub без токена** — 10 запросов в минуту: прицельный поиск успевает меньше технологий.

## 5. Этап 4.3: архив новостей, корпус arXiv, оценка возникновения

См. `docs/collector/DECISIONS.md`, раздел «Этап 4.3». Наполнение архивов — в контейнере collector:

| Команда | Что делает | Когда |
|---|---|---|
| `python -m collector.tools.archive wayback` | Адреса статей изданий из Wayback, с `WS_ARCHIVE_WAYBACK_FROM` по текущий месяц. Повторный запуск продолжает и обновляет последние месяцы | Первичная загрузка, затем раз в месяц |
| `python -m collector.tools.archive rss` | Все записи всех RSS-лент | Ежедневно |
| `python -m collector.tools.archive arxiv` | Корпус arXiv через OAI-PMH, возобновляемо | Первичная загрузка, затем раз в месяц |
| `python -m collector.tools.archive status` | Сводка архива и корпуса | Перед прогоном |

Измерение: короткие названия (OCS, PBM, SMR, MMF, KYA, НПЗ) теперь учитываются отдельным словом в верхнем
регистре. Это исправление измерения, а не поиска: в отчётах оно показано отдельно.
