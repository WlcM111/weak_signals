**Эксперимент B1.** Сравнивались бинарные признаки (без деления на √n) и текущая нормировка на тех же разбиениях:

| Вариант | CV у организаторов | Перенос своё → организаторы, recall | По доменам | Связь оценки с длиной, ρ |
|---|---|---|---|---|
| Текущий, 1/√n | 0,907 | 0,14 | 0,880 | 0,32 |
| Бинарный, без длины | 0,862 | 0,06 | 0,853 | 0,35 |
| Baseline «только длина» | 0,916 | — | — | — |

Бинарный вариант хуже по всем метрикам, и связь с длиной у него не слабее. Длина приходит не только через нормировку:
длинные позитивы организаторов содержат больше «сигнальных» основ. Правило плана — принимать только при победе над
baseline длины на тесте без конфаунда, а такого теста нет до этапа 4. Числа получены в песочнице (scikit-learn 1.8);
в образе trainer (1.9.1) их пересчитывает команда из раздела 3.

## 4. Риски и ограничения

- Если соединение с GDELT в вашей сети не устанавливается и за 20 с, история новостей не придёт. Тогда нужен второй
  новостной поиск — это отдельное решение, по фактам диагностики.
- Bulk-поиск Semantic Scholar сортирует по дате, а не по релевантности. Свежие статьи по точной фразе могут оказаться
  шумнее; это покажет прогон.
- Отбор GDELT по окнам распределяет 150 документов источника по истории. Каждое окно даёт не более 19 самых
  релевантных статей.

## 5. Этап 3.1 (06.10.2026): по результатам прогона этапа 3

### Факты прогона и диагностики

- **GDELT.** Опрашивается во всех темах, таймаутов нет, но первый же запрос получает 429. Диагностика из контейнера
  collector после 70 с без запросов дала 429 и для свежих статей, и для окна 2025-01..03. Текст ответа: «Please limit
  requests to one every 5 seconds or contact … for larger queries. All high-traffic users should switch to our ngrams
  dataset». GDELT ограничивает адрес стенда независимо от частоты запросов, кодом это не исправить.
- **Semantic Scholar.** Отказов 429 больше нет (этап 3), но точная фраза в кавычках почти ничего не находит для длинных
  фраз: «инфраструктура для ИИ» — 97 → 1 документ, «робототехника» — 0.
- **Проверка доступности источников** адаптерами проекта: 7 из 7 доступны, Википедия отвечает, ленты RSS — 26 из 26,
  Hacker News Search — код 200.
