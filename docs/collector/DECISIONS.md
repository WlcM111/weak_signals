## 2026-09-27 — базовый образ collector на Debian 12 (bookworm) из-за отказов CDN arXiv

**Факт.** В образе `python:3.12-slim` (Debian 13 trixie, Python 3.12.14, OpenSSL 3.5.7) каждый запрос к
`export.arxiv.org` без ответа в кеше CDN получал 406 с пустым телом. В `via` были только узлы Varnish без
`google`, стоял `cache-control: private, no-store`, путь в `x-served-by` обрывался на узле LGA — до серверов
arXiv запрос не доходил. Матрица 26.09.2026 (один IP, одна сеть Docker, одинаковые запросы с паузой 8 с):

| Образ | Python | OpenSSL | Результат |
|---|---|---|---|
| `weak-signals/collector:1.0.0` (slim, trixie) | 3.12.14 | 3.5.7 | 406, 406 |
| `python:3.12-slim-trixie` | 3.12.14 | 3.5.7 | 406, 406 |
| `python:3.12-slim-bookworm` | 3.12.14 | 3.0.20 | 200, 200 |

**Решение.** Базовый образ collector — `python:3.12-slim-bookworm` (OpenSSL 3.0). Остальные сервисы с arXiv не
работают и не меняются.

**Как не сломать снова.**
- Переход collector на trixie (или новый тег `slim`) — только после повторной проверки матрицей образов.
- При старте collector пишет в журнал `openssl` — смена TLS-библиотеки после обновления образа видна сразу.
- Отказ HTTP сохраняет заголовки `via`, `x-cache`, `x-served-by`. 406 без узла `google` в `via` помечается
  текстом «CDN arXiv отклонил TLS-клиент, запрос не дошёл до сервера» (код HTTP_4XX — контракт не меняется).
- Для arXiv — отдельный HTTP-клиент без внутренних повторов: шлюз частоты и 30-минутная пауза адаптера
  закрывают все отказы, а повторы 429/5xx в обход шлюза нарушали бы правило arXiv о частоте.
- Статьи arXiv продолжают приходить и через OpenAlex, если API arXiv снова откажет.

### Трасса сбора (этап 2, аудит A3)

`BaseSourceAdapter._fetch` записывает итог каждого логического запроса: адрес без ключей и учётных данных, код
отказа или сжатое тело ответа с SHA-256. Заголовки не записываются. `RunCollection` записывает событие для каждого
документа, выданного адаптером: принят, дубль, лимит источника, отбракован нормализацией. Записи сбрасываются вместе
с партиями документов. Сбой записи не обрывает сбор, а виден в журнале и счётчике `trace_save_failures`. Таблицы —
`raw_responses`, `document_events`, выключатель — `WS_COLLECTOR_TRACE_ENABLED`.

### Этап 3: GDELT, бюджет и паузы, Semantic Scholar Bulk

- **GDELT.**
  - Ищет окнами по 90 дней: DOC API ищет с 2017 года, но artlist отдаёт только последние 3 месяца окна.
  - Пауза для следующих сборов — только после 429 или текста вместо JSON, 120 с. Таймаут соединения 20 с, один повтор окна.
- **Политика источника (B2-b):** бюджет запросов на сбор, повторы после 429, пауза без `Retry-After`. Каждая попытка —
  отдельная запись трассы.
- **Semantic Scholar:** bulk-поиск, новые первыми, в окне 24 месяца.

Обоснование и факты — `docs/stages/STAGE3_REPORT.md`.

### Этап 3.1: Hacker News вместо GDELT, Semantic Scholar по всем словам

- **GDELT.** Отвечает стенду 429 даже после минуты тишины — ограничивает адрес. Отключается настройкой
  `WS_SOURCE_ENABLED_OVERRIDE=gdelt=false`, код источника остаётся.
- **Hacker News Search (Algolia):**
  - история публикаций окнами по 90 дней, все слова фразы;
  - документ — заголовок и ссылка на исходную статью;
  - тип — по домену ссылки (`by_domain`), доверенность не выше MEDIUM;
  - в каталоге назван «Search by Algolia», как просит документация API.
- **Semantic Scholar.** Точная фраза в кавычках почти ничего не находила для длинных фраз, поэтому запрос — все слова.

### Этап 4: поиск «от темы к технологиям»

- **Факт.** Ни одна из 285 ссылок экспертов не попала в собранное за три прогона. Запросы были пересказом темы
  («edge security», «AI security systems»), выдача — самые новые или самые популярные работы. Даже точными
  названиями технологий наши адаптеры находили только 37 из 100: И всех слов фразы в arXiv и Semantic Scholar
  давал 0 документов в 29 и 21 случае, GitHub отказывал по частоте.
- **Решение.** Два прохода:
  - широкий — по фразам темы, с меньшим лимитом на источник (кроме RSS);
  - извлечение названий технологий из его заголовков — статистика, без LLM;
  - прицельный — по технологиям от модели и извлечённым: релевантность в окне дат, по 3 документа
    на технологию в каждом источнике.
- **Архивы изданий.** Не подключались: условия использования TechCrunch запрещают автоматическое извлечение
  данных. Новости — только через RSS: лента предназначена для автоматического чтения.

### Этап 4.2: надёжность запросов (аудит API и диагностика 07.10.2026)

- **Один владелец повторов.**
  - HTTP-клиент источников делает одну попытку.
  - Повторы — в адаптере, и каждая попытка заново проходит лимитер: после 429 — по политике `retries`,
    после сетевого сбоя, таймаута и 5xx — `transient`, с общей паузой 2 с.
  - Прежде вложенные повторы давали до 12 HTTP-попыток на запрос мимо лимитера.
- **Лимитер:**
  - ёмкость 1 — без стартового всплеска;
  - общая пауза `blocked_until` после 429 и квотного 403 видна всем задачам источника;
  - новая пауза только продлевает действующую.
- **Частоты по опубликованным правилам:**
  - GitHub Search: 10 запросов в минуту без токена, 30 с токеном;
  - Wikipedia: 200 запросов в минуту;
  - arXiv: не чаще раза в 3 с;
  - Zenodo Search: 30 запросов в минуту;
  - Semantic Scholar: с ключом — 1 запрос в секунду.
- **Квотный 403 GitHub** (`x-ratelimit-remaining: 0`) — `RATE_LIMITED` с паузой до сброса квоты.
- **Сетевые ошибки** — `NETWORK_ERROR`, а не `HTTP_5XX`.
- **Редиректы.** Выполняются вручную: хост каждого перехода проверяется по белому списку, ключи не уходят
  на другой origin.
- **RSS:**
  - заголовок `Accept` для лент — PR Newswire без него отвечал 301 → 404;
  - разбор RSS 1.0 (RDF);
  - не-лента — `PARSE_ERROR`;
  - отказ всех лент — отказ источника, а не пустая выдача;
  - записи лент сверяются и с технологиями от модели — без новых запросов.
- **arXiv в прицельном проходе не участвует:** один 429 выключал его на 30 минут, а препринты arXiv ищет OpenAlex.
  **Semantic Scholar прицельно — только с ключом.**
- **GDELT:** запросы не менялись; повтор после сбоя — только собственный повтор окна адаптера.

### Этап 4.3: архив новостей, корпус arXiv, оценка возникновения

- **Факты анализа:**
  - 29 из 37 технологий, которые наши источники находят по точному названию, система не запрашивала;
  - извлечение из широкого прохода не может их дать: 0 из 100 пригодны в документах прогона;
  - у 46 сигналов есть новостная ссылка, в 52 из 68 адресов есть слово из словаря темы;
  - Wayback хранит 9 из 12 проверенных статей; его поиск по префиксу работает без авторизации.
- **Архив новостей.**
  - Адреса статей 27 изданий из Wayback CDX — раз в месяц, по месяцам, возобновляемо.
  - Все записи RSS — при каждом сборе и командой `rss`.
  - Поиск по словам (`tokens @>`, GIN) без внешних запросов во время задания.
  - Страницы из архива не загружаются: заголовок — слова адреса.
- **Корпус arXiv** — OAI-PMH, наборы cs, eess, q-fin: работы с 2021 года, заголовок и начало аннотации.
- **Оценка возникновения:**
  - рост доли словосочетания заголовков в недавнем периоде к базовому;
  - статьи arXiv: последние 24 месяца против 2021 года и позже; новости: 6 месяцев против предыдущих 12;
  - отсев общих тем и зрелых областей.
- **Порядок технологий прицельного прохода:** корпуса → извлечённые → модель (не больше 10). Второй круг —
  названия из документов прицельного прохода.
- **Близость к запросу.** На уровне кандидата — совпадение со словами фраз темы в корпусе; на уровне документов —
  эмбеддинги e5 в analyzer, как и раньше. Отдельный RPC эмбеддингов не добавлялся: collector стал бы зависеть
  от analyzer, а analyzer уже зависит от collector — получился бы цикл.
- **Чего нет:** Common Crawl не добавлялся, GDELT не трогался — по решению владельца.

### Этап 4.4: выборка корпуса, бюджет документов, ранжирование архива

- **Факты быстрого замера 10.10.2026** (12 из 100):
  - технологий из корпусов по темам: 0, 2, 1, 2, 25, 25. Работа попадала в выборку, только если в ней были все
    слова фразы темы, а длинные фразы модели почти ничего не находили;
  - в 4 темах из 6 сбор упёрся в 800 документов;
  - архив новостей дал 47–108 документов на тему, но с экспертами совпал 1 сигнал.
- **Диагностика архива:** из 66 экспертных ссылок на издания архива в нём есть 45 (35 сигналов). Значит, статьи
  в архиве были, но поиск «новые первыми» по общим фразам их не поднимал.
- **Решения:**
  - выборка корпуса — хотя бы 2 ключевых слова темы без общих («ai», «systems»), периоды выбираются отдельно,
    порог числа документов — под размер выборки;
  - лимит сбора 1200, прицельному проходу — 600 мест, второму кругу — 200;
  - Crossref, Hugging Face и архив в широком проходе — 20, 10 и 20;
  - архив новостей — в основном по технологиям, по числу совпавших слов, обе формы числа, 5 статей на технологию.

### Этап 4.5: канал «события стартапов» и чистая оценка возникновения по новостям

- **Факты:**
  - в архиве 45 экспертных статей (35 сигналов), а быстрый замер 4.4 через архив нашёл 2 сигнала;
  - выборка «событие стартапа + хотя бы 2 ключевых слова фраз темы» не взяла ни одной из 45 даже в топ-500;
  - у 29 из 53 экспертных статей нет ни одного ключевого слова фраз темы, хотя бы 2 — только у 5;
  - со словами технологий, которые система уже отбирает, хотя бы 2 общих слова — у 34 из 68;
  - 49 из 66 экспертных новостей — события стартапов.
- **Причина.** Фразы темы от модели общие, а экспертные статьи — о конкретных технологиях. Поиск, построенный на
  словах фраз темы, до экспертных статей не дотягивается.
- **Решение:**
  - словарь канала — слова темы и отобранных технологий;
  - порядок — по сумме редкости совпавших слов внутри выборки, без внешних запросов.
- **Оценка по новостям.** Слова адресов Wayback склеивались в мусор («capital factory built nuclear», «germany
  semiconductor memory market»), поэтому оценка идёт только по заголовкам RSS, а шаблоны отчётов отсеиваются.
