### Фактические метрики обученной модели

Отложенный тест (45 строк, использован один раз): **accuracy 0.978, precision 0.952,
recall 1.000, F1 0.976, ROC-AUC 0.998**. CV (5×5): F1 0.976 ± 0.026. Порог 0.416.
Полный отчёт с доверительными интервалами и разрезами — `docs/ml/evaluation_report.md`.

**Эти числа нельзя трактовать как качество на скрытой проверке организаторов.** Две причины
изложены в отчёте и повторены здесь, потому что они принципиальны:

1. Отрицательный класс написан командой. Опорное решение B1 (TF-IDF по словам, без признаков
   реестра) даёт F1 0.959 — то есть классы почти полностью различимы по лексике и стилю.
   Длина текста у классов почти не пересекается: позитивы 204–401 символ, негативы 62–206.
2. Контрольный прогон «только название» (`--text-mode title`, описания удалены у обоих классов)
   даёт **accuracy 0.644, F1 0.500, CV F1 0.630**. Разница показывает, что основная часть качества
   в основном прогоне обеспечивается описаниями, а не названием технологии.

Вывод: модель и конвейер работоспособны, протокол оценки честный, но набор данных требует
доработки (выравнивание стиля негативов), прежде чем метрики можно будет предъявлять как
достижение порога 75–80 % из ТЗ.

## Что НЕ проверялось

| Область | Причина | Что готово для получателя |
|---|---|---|
| Обучение на реальных эмбеддингах e5 | нет `torch`/`sentence-transformers` и сети | адаптер переиспользует `E5Embedder` analyzer; запуск — `ml.cli train --embedder e5` |
| Обогащение через collector (`enrich`) | нет `grpcio` и сети | клиент переиспользует `CollectorGrpcClient` analyzer; есть `--fixtures` для офлайна |
| Коллекционные и энциклопедические признаки (14 из 25) | следствие предыдущего пункта | в текущем прогоне они принимают значения «пустой коллекции», вклад в модель нулевой |
| Baseline B3 (LightGBM) | пакет не установлен | код готов, в отчёте помечен «не запускался» |
| MLflow-трекинг | пакет не установлен | использован файловый журнал `ml/reports/runs.jsonl` |
| Перекрёстная разметка и каппа Коэна | нужен второй аннотатор | инструменты готовы и покрыты тестами; см. `docs/ml/labeling_protocol.md` §5 |
| Сборка образа trainer, `docker compose --profile ml` | нет Docker | Dockerfile написан по образцу collector/analyzer |
| `ruff`, `mypy` | пакеты недоступны | не запускались |

## Известные ограничения

1. Каппа Коэна не вычислена — прямое расхождение с критерием приёмки §20.1 задания на ML-конвейер.
2. Артефакт, обученный хеширующим эмбеддером, непригоден для analyzer с e5 — это ожидаемое
   поведение проверки совместимости, а не дефект. Для рабочего контура требуется прогон с e5.
3. Правила §12.6 на текущем наборе не исключают ни одного позитива, поэтому требование «≤ 5 %»
   выполнено тривиально: после появления коллекционных признаков калибровку нужно повторить.
