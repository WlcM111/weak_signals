# Карточка модели v2 (logreg_seq_laplace)

**Назначение.** Ранжирование кандидатов слабых сигналов в analyzer по теме запроса: вероятность, что кандидат — релевантный теме ранний проверяемый технологический сигнал (рубрика — `ml/data/dataset_b/LABELING_PROTOCOL.md`). Не предназначена для оценки описаний, написанных в стиле датасета организаторов, и не заменяет экспертизу.

**Архитектура.** Логистическая регрессия на 37 признаках v2 (ARCHITECTURE.md, ADR-1), калибровка Платта, порог max-F1 на dev. Обучение последовательное: Stage A (A-train, названия) → Stage B (dev-фолды B, старт из θ_A, лапласовский/L2-SP якорь, опционально replay A-train).

**Данные.** A: 100 позитивов организаторов + 125 негативов команды (один аннотатор). B: `dataset_b_v1` — 153 размеченных строки (26 позитивов), 18 неопределённых, 18 тем; разметка `llm_assisted_silver`, ожидает экспертной проверки.

**Качество.** Проверенные числа — только для хеширующего эмбеддера в контейнере (RESULTS.md): прирост над производственным score **не доказан**, приёмка `reject_keep_current_model`. Качество на e5 определяется прогоном на Mac; до `accept` модель v2 не активируется.

**Ограничения.** Малый B (19 позитивов в dev); silver-разметка одной моделью; стилевой сдвиг A (длина названия разделяет классы A с ROC-AUC 0,901); признак `rel_cluster_query_v1` зависит от LLM-расширения запроса; для 12 строк веб-поиска он импутирован медианой dev.

**Риски и контроль.** Ложные сигналы при узких темах; дрейф источников. Контроль: журнал `holdout_usage.jsonl`, абляции `WS_ML_SCORE_ABLATION`, откат `seq-activate`.
